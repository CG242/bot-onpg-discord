1. PRÉSENTATION GÉNÉRALE
================================================================================

OBJECTIF :
  Bot Discord pour gérer un championnat de FT (Fighting Tournament) entre joueurs.
  
FONCTIONNALITÉS PRINCIPALES :
  ✓ Enregistrement automatique des scores
  ✓ Classements dynamiques par région (BZ, PN)
  ✓ Système de rangs et ELO pour chaque joueur
  ✓ Historique complet des matchs
  ✓ Commandes slash (/) intuitives
  ✓ Synchronisation automatique toutes les 3 minutes
  ✓ Liens Discord↔Pseudo

LANGUES :
  - Interface : Français
  - Code : Python 3.12+
  - Base : MySQL 8.0+

RÉGIONS SUPPORTÉES :
  - BZ (Brazzaville)
  - PN (Pointe-Noire)

TYPES DE MATCHS :
  - FT2, FT3, FT5, FT7, FT10
  (Déterminés par le score maximum)

4. FLUX DE TRAITEMENT COMPLET D'UN SCORE
================================================================================

ÉTAPE 1 : UTILISATEUR POSTE UN SCORE
────────────────────────────────────
  Message Discord dans #scores-ft-congo :
    "Leleo242 5 - 1 Toto99"

ÉTAPE 2 : BOT DÉTECTE LE MESSAGE
────────────────────────────────────
  Fonction : bot.py → on_message(message)
  
  Vérifie :
    ✓ Le bot n'est pas l'auteur (message.author.bot)
    ✓ Le message est dans un salon #scores (is_scores_channel)
    ✓ Le message n'est pas un robot Discord
    ✓ Date > START_DATE

ÉTAPE 3 : PARSER EXTRAIT LES SCORES
────────────────────────────────────
  Fonction : parser.py → parse_all_matches(content)
  
  Regex : (\d+)\s*-\s*(\d+)
  
  Extrait :
    player1 = "Leleo242"
    score1 = 5
    score2 = 1
    player2 = "Toto99"
    ft_type = MAX(5, 1) = 5
    winner_side = 1 (score1 > score2)
  
  Retour : list[ParsedMatch]

ÉTAPE 4 : BOT SYNCHRONISE LES MATCHS
────────────────────────────────────
  Fonction : bot.py → _sync_message_scores_sync(message)
  
  4.1 Compare signature old vs new
      old_signature = db.get_message_match_signature(message_id)
      new_signature = parse_all_matches(message)
      
      Si identique → Retour (rien à faire)
      Si changement → Supprime anciens matchs
  
  4.2 Détermine la région
      score_region = self.get_score_region(message)
      
      Si message dans #scores-bz → "BZ"
      Si message dans #scores-pn → "PN"
      Si message dans #scores (générique) → None
  
  4.3 Crée les joueurs s'ils n'existent pas
      player1 = db.get_or_create_player(parsed.player1, discord_id_1)
      player2 = db.get_or_create_player(parsed.player2, discord_id_2)
      
      Cherche @mentions dans message.mentions
      Essaie de matcher par nom Discord
  
  4.4 Attribue la région si salon régional
      Si score_region in ["BZ", "PN"]:
          db.set_player_region(player1["id"], score_region)
          db.set_player_region(player2["id"], score_region)
  
  4.5 Insère le match
      winner_id = player1["id"] si parsed.winner_side == 1 else player2["id"]
      
      db.insert_match(
          message_id=message.id,
          match_index=0,
          season_id=season["id"],
          player1_id=player1["id"],
          player2_id=player2["id"],
          score1=parsed.score1,
          score2=parsed.score2,
          ft_type=parsed.ft_type,
          winner_id=winner_id,
      )

ÉTAPE 5 : POINTS ELO RECALCULÉS
────────────────────────────────
  Fonction : ranking.py → compute_match_elo_delta(ft_type, won)
  
  TABLE DE BONUS PAR FT :
  ┌────────┬─────────┬──────────┐
  │ FT     │ Victoire│ Défaite  │
  ├────────┼─────────┼──────────┤
  │ FT2    │ +25     │ -15      │
  │ FT3    │ +27     │ -16.5    │
  │ FT5    │ +30     │ -17.5    │
  │ FT7    │ +33     │ -19      │
  │ FT10   │ +37     │ -21      │
  └────────┴─────────┴──────────┘
  
  Victoire  : +25 + BONUS[ft_type]
  Défaite   : -15 - BONUS[ft_type]/2
  
  Base ELO ne descend jamais sous 0 (GREATEST(0, elo + delta))

ÉTAPE 6 : MISE À JOUR AUTOMATIQUE
────────────────────────────────────
  Toutes les 180 secondes (config.AUTO_SYNC_SECONDS)
  
  Fonction : bot.py → _auto_sync_loop()
  
  1. Récupère tous les messages des salons #scores
  2. Chaque message → vérifie signature
  3. Si modification → resynchronise
  4. Recalcule tous les points ELO
  5. Récupère nouveau leaderboard
  6. Format en texte Discord
  7. UPDATE message(s) dans #classement

6. SYSTÈME DE RANGS & ELO
================================================================================

HIÉRARCHIE DES RANGS
──────────────────────

Rang     | Points de base | Description
─────────┼────────────────┼─────────────────────────
S+       | 2400           | Meilleur tier
S        | 2200           | Très bon
A+       | 2000           | Bon
A        | 1800           | Compétent
B+       | 1600           | Intermédiaire
B        | 1400           | Début/Régulier
NR       | 1000           | Non Classé (défaut)

SYSTÈME ELO
────────────

Un joueur a un ELO (points) qui varie selon ses matchs.

POINTS DE BASE :
  Base victoire : +25
  Base défaite  : -15

BONUS PAR TYPE FT :
  FT2  : +0
  FT3  : +2
  FT5  : +5
  FT7  : +8
  FT10 : +12

CALCUL COMPLET :
  Victoire  = +25 + BONUS
  Défaite   = -15 - (BONUS / 2)

EXEMPLES :
  FT5 Victoire  : +25 + 5   = +30
  FT5 Défaite   : -15 - 2.5 = -17.5
  FT10 Victoire : +25 + 12  = +37
  FT10 Défaite  : -15 - 6   = -21

RÈGLES :
  • ELO jamais négatif (GREATEST(0, elo + delta))
  • Rang manuel (rank_manual=1) reste fixe jusqu'à admin le change
  • Rang auto (rank_manual=0) = peut être recalculé
  • Points initiaux = points du tier attribué

AFFICHAGE :
  Dans les classements, ordre de tri :
    1. Victoires DESC (plus haut = mieux)
    2. Défaites ASC (moins = mieux)
    3. Ratio points (points marqués / points concédés) DESC
    4. ELO DESC
    5. Pseudo alphabétique ASC

7. GESTION DES JOUEURS
================================================================================

CRÉATION AUTOMATIQUE
──────────────────────

Quand un score est posté avec un pseudo qui n'existe pas :

1. Nettoie le nom :
   - Supprime les annotations (texte entre parenthèses)
   - Supprime les scores du nom
   - Limite à 64 caractères
   - Normalize : minuscules, sans "Le" devant

2. Cherche le joueur par normalized_name
   Si trouvé :
     - Retour joueur existant
   
   Si pas trouvé :
     - Crée nouveau joueur
     - discord_id = null (sauf si mention trouvée)
     - tier_rank = "NR"
     - elo = 1000
     - rank_manual = 0

3. Essaie matcher avec @mention dans message
   Si match trouvé :
     - Set discord_id = mention.id

EXEMPLE D'EXTRACTION :
  Message : "Leleo242 5 - 1 Toto99"
  
  Brut      : "Leleo242"
  Sanitized : "leleo242"
  Display   : "Leleo242"
  
  En BD :
    name = "Leleo242"
    normalized_name = "leleo242"
    discord_id = null (sauf si @mention trouvée)

RÉSOLUTION DE JOUEUR
──────────────────────

Fonction : player_resolver.py → resolve_player_input(db, input, season_id)

Cherche dans cet ordre :
  1. Par mention Discord (@user)
  2. Par normalized_name (exact match)
  3. Par fuzzy match (similitude)
  4. Si ambigu : affiche menu de sélection

Retour : ResolveResult
  - found (bool) : trouvé ou pas
  - player (dict) : données du joueur ou null
  - label (str) : affichage pour l'utilisateur
  - search_text (str) : texte cherché

LIEN DISCORD↔PSEUDO
──────────────────────

Permet de lier un compte Discord à un pseudo de joueur :

AVANTAGES :
  • Chercher joueur par @mention
  • Attribuer rangs/régions par @mention
  • Afficher le display name Discord

FONCTIONS :
  • db.link_discord_id(player_id, discord_id)
  • db.get_player_by_discord_id(discord_id)

EXEMPLE :
  Avant : pseudo "Leleo242" sans lien
  Après : /link pseudo:Leleo242 membre:@Leleo
  → discord_id = 123456789

MAINTENANT :
  • /stats membre:@Leleo → trouve Leleo242
  • /set-rang rang:S+ membre:@Leleo → met à jour S+

8. SYNCHRONISATION AUTOMATIQUE
================================================================================

BOUCLE AUTO-SYNC
─────────────────

Lancée au démarrage du bot, tourne indéfiniment.

Fonction : bot.py → _auto_sync_loop()

PSEUDO-CODE :
  while True:
    sleep(AUTO_SYNC_SECONDS)  # 180 sec par défaut
    try:
      await sync_all_guilds(quiet=True)
    except Exception:
      logger.exception("Erreur sync")

COMPORTEMENT LORS DE LA SYNC
──────────────────────────────

Pour chaque serveur Discord (guild) :
  
  1. Récupère tous les messages des salons #scores
     - Si SCORES_CHANNEL_BZ défini → inclut ce salon
     - Si SCORES_CHANNEL_PN défini → inclut ce salon
     - Si SCORES_CHANNEL défini → inclut ce salon
  
  2. Pour chaque message :
     - Récupère sa signature BD (anciens matchs)
     - Parse le contenu actuel
     - Compare signatures
     
     Si changement :
       - Supprime anciens matchs
       - Enregistre nouveaux matchs
       - Recalcule les points ELO
  
  3. Récupère le leaderboard mis à jour
  
  4. Récupère ou crée le message de classement dans #classement
  
  5. UPDATE le message avec le nouveau classement
  
  6. Log les infos (nombre de matchs synced, etc)

RÉSULTAT :
  ✓ Classement toujours à jour
  ✓ Même si scores modifiés
  ✓ Même si bot redémarré
  ✓ Même si nouvelle saison

STOCKAGE DES IDS DE MESSAGES
──────────────────────────────

Les IDs des messages de classement sont stockés dans bot_settings :

Clé : leaderboard_message_ids_GUILD_ID
Valeur : "ID1,ID2,ID3"

Permet de mettre à jour plusieurs messages de classement.

EXEMPLE :
  leaderboard_message_ids_123456789 = "987654321,987654322"
  → Met à jour 2 messages

BUG CORRIGÉ : MySQL 1247 - "Reference not supported"
────────────────────────────────────────────────────

SYMPTÔME :
  mysql.connector.errors.ProgrammingError: 1247 (42S22)
  Reference 'loss_points_scored' not supported
  (reference to group function)

CAUSE :
  La requête SQL utilisait une expression complexe dans ORDER BY
  avec des alias d'agrégation (SUM) et GROUP BY
  
  Code problématique :
  ORDER BY
      ft_wins DESC,
      ft_losses ASC,
      (loss_points_scored / GREATEST(loss_points_conceded, 1)) DESC,  ❌
      elo DESC,
      normalized_name ASC

EXPLICATION TECHNIQUE :
  • MySQL refuse d'utiliser une expression avec alias d'agrégation
    directement dans ORDER BY quand un GROUP BY existe
  • loss_points_scored = SUM(...) alias
  • loss_points_conceded = SUM(...) alias
  • On ne peut pas diviser deux alias d'agrégation en ORDER BY

SOLUTION :
  Utiliser une sous-requête pour que les agrégations soient calculées
  AVANT l'ORDER BY
  
  Code corrigé :
  SELECT ... FROM (
      SELECT
          p.id,
          ...
          SUM(...) AS loss_points_scored,
          SUM(...) AS loss_points_conceded
      FROM matches m
      JOIN players p ...
      GROUP BY ...
  ) AS leaderboard
  ORDER BY
      ft_wins DESC,
      ft_losses ASC,
      (loss_points_scored / GREATEST(loss_points_conceded, 1)) DESC,  ✓
      elo DESC,
      normalized_name ASC

COMMIT GIT :
  48fe4f2 - "fix(database): corrige erreur MySQL 1247..."
  Fichier : database.py → get_leaderboard()

VÉRIFICATION :
  Après correction, le bot démarre sans erreur.
  /classement affiche le leaderboard normalement.
